# GIT - Manuale Completo

## Cos'è Git

Git è un sistema di controllo di versione distribuito (DVCS) che permette di:

- tracciare le modifiche ai file
- salvare istantanee del progetto (commit)
- collaborare con altri sviluppatori
- gestire più versioni dello stesso progetto attraverso i branch

---

# Architettura di Git

Git lavora principalmente con tre aree:

```text
Working Directory
       ↓
Staging Area
       ↓
Repository
```

## Working Directory

Contiene i file reali su cui stiamo lavorando.

Esempio:

```text
README.md
src/
docs/
```

---

## Staging Area

Area temporanea dove vengono preparate le modifiche che entreranno nel prossimo commit.

```bash
git add file.txt
```

---

## Repository

Contiene lo storico completo del progetto:

- commit
- branch
- tag
- cronologia

---

# Salvare un'Istantanea

## Stato del repository

```bash

```

Mostra:

- file modificati
- file nella staging area
- file non ancora tracciati

---

## Aggiungere file alla staging area

Tutti i file:

```bash
git add .
```

Singolo file:

```bash

```

---

## Creare un commit

Commit con editor:

```bash
git commit
```

Commit con messaggio:

```bash
git commit -m "Aggiunta gestione errori"
```

---

## Modificare l'ultimo commit

```bash

```

Permette di:

- correggere il messaggio
- aggiungere un file dimenticato
- unire piccole modifiche al commit precedente

# Merge

Permette di unire due rami.

---

## Fast Forward Merge

Situazione:

```text
A---B---C(main)
         \
          D---E(feature)
```

Comando:

```bash
git merge feature
```

Risultato:

```text
A---B---C---D---E
```

Caratteristiche:

- nessun conflitto
- nessun commit di merge
- Git sposta semplicemente il puntatore del branch

---

## Three-Way Merge

Situazione:

```text
      C(feature)
     /
A
     \
      B(main)
```

Entrambi i branch hanno introdotto modifiche.

Comando:

```bash
git merge feature
```

Git crea un commit di merge.

---

# Conflitti di Merge

Se entrambi i branch modificano la stessa porzione di file:

```text
<<<<<<< HEAD
Versione MAIN
=======
Versione FEATURE
>>>>>>> feature
```

Occorre:

1. modificare manualmente il file
2. eliminare i marcatori Git
3. salvare

Successivamente:

```bash
git add file.txt
git commit
```

---

# Regole del Merge

Le righe eliminate in un branch vengono eliminate anche nell'altro se non modificate.

Le righe modificate in un branch vengono aggiornate nell'altro se nessuno le ha modificate.

Se entrambi modificano la stessa sezione:

```text
Conflitto
```

# Rebase

Permette di aggiornare un branch con le modifiche più recenti di un altro branch.

Entrare nel branch:

```bash
git checkout feature
```

Eseguire:

```bash
git rebase main
```

Vantaggi:

- cronologia più lineare
- merge futuri più semplici
- maggiore probabilità di Fast Forward Merge
